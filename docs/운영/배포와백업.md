## 플러그인 빌드

개발 프로젝트 `ServerCore_2`에서 Java 25로 실행합니다.

```powershell
.\gradlew.bat build
```

결과는 `build/libs/ServerCore-3.14.0.jar`입니다. `check`에는 부지 순서와 저장·재시작 회귀 검사가 연결되어 있습니다.
배포용 사본은 서버 저장소의 `release/`에 둘 수 있습니다. 소스 빌드 버전과 실행 버전은 다를 수 있습니다.

서버를 정상 종료하고 월드·플러그인 데이터·설정을 저장소 밖에 백업합니다.
서버 `plugins/`에는 ServerCore JAR를 한 개만 남기고 새 파일로 교체한 뒤 재시작합니다.
`/version ServerCore`로 실제 적용 버전을 확인합니다. 기존 `guide.yml`에는 옛 확장 안내가 남을 수 있으므로 새 `src/main/resources/guide.yml`과 비교해 집 부지 안내 부분을 갱신합니다. 운영 월드를 개발 PC 월드로 덮어쓰지 않습니다.

## 리소스팩

개발 프로젝트의 `tools` 폴더에서 필요할 때 실행합니다.

```powershell
python make_tool_models.py --preview
python build_pack.py --jar "$env:APPDATA\.minecraftersions.3.3.jar" --dogam "D:\Games\minecraft\Server\Server_Pack\server_pack\plugins\ServerCore\dogam.yml"
```

모델 생성에는 Pillow·numpy, 팩 빌드에는 Pillow·PyYAML이 필요합니다.
생성기는 수동 수정한 모델을 덮어쓰므로 모델을 직접 편집했다면 먼저 보관합니다.
`tools/build/servercore_pack.zip`을 업로드하고 `resource-pack` URL과 `resource-pack-sha1`을 갱신합니다.
집터 2×2 로직 변경 자체는 새 그림을 요구하지 않으므로 이것만으로 팩 재빌드가 필요하지는 않습니다.

## Git과 월드

Git은 파일 동기화이며 실행 중 월드의 일관된 백업을 대신하지 않습니다.
월드를 추적하던 저장소에서 추적 해제 커밋을 받으면 서버 파일이 삭제될 수 있습니다.
`.gitignore`를 바꾸기 전에는 운영 월드를 저장소 밖에 백업하고 전환 후 복원합니다.
지금 문서 정리 작업은 ignore·추적 상태·원격 기록을 변경하지 않습니다.

```text
git status
git log -5 --oneline
git diff --name-status HEAD..origin/main
```

배포 전에 변경 목록을 확인합니다. 충돌이 나면 멈춰서 로컬과 OCI 중 어느 데이터를 남길지 결정합니다.
`git reset --hard`, `git clean`, 강제 푸시는 정상적인 배포 절차에 넣지 않습니다.
`.env`뿐 아니라 설정 안의 비밀번호·토큰도 커밋 전 확인합니다.

월드 복구는 최신 운영 백업을 우선합니다. Git 커밋은 그 커밋 시점에 저장된 파일만 복원합니다.
`git archive`로 별도 폴더에 추출하는 것과 실행 중인 `world/`를 복원하는 것은 다릅니다.

## 통합 리소스팩 릴리스 관리

리소스팩 변경 후 `deemo777/minecraft_server`의 `servercore` 릴리스에서 `servercore_pack.zip`을 교체합니다. [릴리스 페이지](https://github.com/deemo777/minecraft_server/releases/tag/servercore)

다운로드 주소는 `https://github.com/deemo777/minecraft_server/releases/download/servercore/servercore_pack.zip`입니다. 업로드 후 다운로드한 ZIP을 로컬 빌드와 비교하고 SHA-1을 확인합니다. `server.properties`의 `resource-pack-sha1`은 새 값으로 바꿔야 하며 주소는 유지됩니다. Git 소스 푸시와 릴리스 파일 업로드는 별개의 작업입니다.

업로드에는 GitHub 릴리스 쓰기 권한을 가진 인증이 필요합니다. 인증 정보는 Git 자격 증명 관리자 등 비밀 저장소에서 사용하고 원격 URL·문서·로그에 넣지 않습니다.
