# 무기와 스킨

종류별 기본 디자인 1개와 추가 스킨 13개, 총 42종을 등록합니다. 스킨 상인에서 종류를 선택해 뽑고 계정 도감에 영구 보관합니다. 스킨은 성능에 영향을 주지 않습니다.

## 스킨 상점·영구 도감 (4.11.0)

- `/npc create skinmerchant` 또는 `/skinmerchantnpc create`로 전용 스킨 상인을 생성합니다. `/skinmerchantnpc remove|face`와 통합 `/npc remove|face skinmerchant`도 지원합니다. 모두 관리자 전용이며 운영 서버에 NPC를 자동 배치하지 않습니다.
- NPC 우클릭 시 대사·첫 만남 과정 없이 4줄 상점이 열립니다. 단검·태도·대검 중 뽑을 종류를 클릭하면 즉시 **100,000G**를 결제합니다. 관리자 미리보기/대리 열기는 `/skinshop [player]`입니다. 집터·무기 보유는 뽑기의 전제 조건이 아닙니다.
- 각 종류의 **추가 스킨 13종 중 미보유 스킨 하나를 동일 확률**로 뽑습니다. 처음에는 각각 1/13, 이후에는 각각 1/남은 수의 확률입니다. 기본 외형은 무료이므로 추첨에서 제외합니다. 중복 획득이 없고 전부 보유하면 추가 결제 없이 도감으로 이동합니다. 선택 창에는 비용만 표시하고, 도감에는 보유 상태만 표시합니다. 조작 방법과 추첨 확률은 아이템 설명에 넣지 않습니다.
- 결과는 아이템이 아닌 UUID별 계정 도감에 등록됩니다. `plugins/ServerCore/money.yml`의 `account-unlocks`에 잔액과 함께 한 번의 파일 교체로 저장합니다. 저장 실패 시 차감과 획득을 모두 되돌립니다. 결과 창을 닫거나 로그아웃해도 이미 저장된 획득은 유지됩니다. 인벤토리 공간은 필요하지 않습니다. 반복 클릭은 같은 상점 창에서 한 번만 결제합니다.
- 상점 아래의 종류별 **도감** 또는 결과의 **도감 열기**로 해당 종류의 5줄 도감을 엽니다. 기본 외형과 추가 13종을 볼 수 있습니다. 같은 종류의 커스텀 무기 한 개를 주손에 들고 보유 스킨을 클릭하면 무료 적용합니다. 미보유·다른 종류·일반 바닐라 무기에는 적용되지 않습니다. 기본 외형 선택도 무료이며 보유 스킨을 소모하지 않습니다.
- 적용은 해당 무기의 `weapon_skin` PDC와 아이템 모델만 바꿉니다. 강화 단계·장인 진행도·내구도·성능·무기 인스턴스를 유지하고, 강화/기존 장비 갱신도 선택한 외형을 보존합니다. 적용된 무기를 다른 사람에게 넘기면 외형은 유지되지만 계정 도감 소유권은 이전되지 않습니다.
- 화면은 보라색 아틀리에와 금색 테두리로 통일했습니다. 종류 선택·획득 결과·도감을 각각 디자인하고 전용 인벤토리 폰트 12조각을 추가했습니다. NPC는 연보라색 머리·베레모·어깨 망토·금색 장식·도안 두루마리를 갖춘 별도 모델입니다. 기존 GUI·NPC와 무기 애니메이션은 유지합니다.

`./gradlew.bat build`의 `verifySkinPurchases`는 결제·저장 실패·재시작·계정 분리·39개 스킨/모델 매핑을 검사합니다. `python tools/verify_skin_shop_pack.py`는 추첨 목록의 모델 존재·폰트·원본 패널 일치·전용 NPC를 검사하고, `python tools/preview_skin_shop.py`는 `tools/build`에 화면 3종과 NPC 정면·사선·뒷면 미리보기를 생성합니다. 미리보기는 ZIP의 모델·UV로 렌더링한 것이며 게임 캡처가 아닙니다.

## 무기 성장

공격력·공속·주변 피해는 `(강화/25)^1.5`를 진행률로 사용하여 0~25강 사이를 매 단계 보간합니다. 초반에는 비슷한 성능, 후반에는 단일/범위 특화가 두드러집니다. 실제 인챈트는 사용하지 않습니다.

| 종류 | 기본 디자인 | 0→25강 공격력 | 0→25강 공속 | 0→25강 주변 피해 비율 | 최대 타격 수 |
|---|---|---|---|---|---:|
| 단검 | iron_dagger | 4→10.7 | 3→4.5 | 10% 고정 | 2 |
| 태도 | uchigatana | 6→13 | 2→2.4 | 20%→77% | 3 |
| 대검 | black_iron_greatsword | 9→24 | 1.3→1.0 | 35%→180% | 5 |

사거리는 기존처럼 단검 2→2.5, 태도 3→3.5, 대검 3.5→4블록을 매 강화 +0.02씩 증가합니다. 최대 타격 수는 직접 대상 포함이며 플레이어의 공격 시점 위치를 중심으로 무기 사거리 안에 있는 가까운 대상부터 선택합니다. 맞은 몹 주변 박스와 기본 3블록 휩쓸기는 사용하지 않습니다. 벽 너머·팀/자신의 길들인 동물·관전자와 PvP 비활성 월드의 플레이어는 제외합니다. 일반 검은 이 제한을 적용하지 않습니다. 보호 기능이 취소한 타격은 되살리거나 다른 대상으로 빈자리를 채우지 않습니다.

주변 피해는 `1+공격력×주변 피해 비율`입니다. 커스텀 무기는 기본 휩쓸기 이벤트를 취소하고 범위 피해를 한 번만 적용하므로 100% 속성 상한에도 영향을 받지 않습니다. 공격 게이지 90% 이상·지상·비질주·비낙하 직접 명중이 있어야 발동하며, 직접 공격 최종 취소 여부를 확인한 다음 틱에 각 대상의 일반 피해/보호 이벤트를 거칩니다. 추가 타격은 다시 범위 공격을 생성하거나 단검·태도의 직접 명중 효과를 발동하지 않습니다. **[0~25강 전체 스탯 표](장비강화_단계별수치.md)**는 실제 런타임 계산식에서 생성합니다.

## 공격 모션

### 무기 표면 애니메이션 (4.10.2)

42종 모두 반복 텍스처 효과를 제공합니다. Azure 단검·태도·대검, Dragon 단검, Spider 단검, Vaelith 대검 6종은 제공된 PNG와 애니메이션 메타데이터 10개를 바이트 그대로 보존합니다.

나머지 36종은 원본 모델·UV·손 위치·첫 프레임·투명도를 보존하고, 팩 빌드 중 16프레임 텍스처를 생성합니다. `tools/weapons`의 원본 이미지는 수정하지 않습니다. 철제는 이동하는 광택, 자수정·어둠은 보랏빛 마력, 서리는 얼음 반짝임, 화염은 주황빛 열기, 피·악마는 붉은 맥동, 룬·눈은 청록빛 마력, 자연·에메랄드는 녹색 흐름, 달·밤·Solstice는 원래 색을 살린 천체 반짝임을 사용합니다. 개별 배정은 `tools/animate_weapon_textures.py`의 `SKINS`에서 확인할 수 있습니다.

8개 테마의 공용 흑백 패턴은 ImageGen 내장 도구로 생성한 `tools/art/weapon_effect_atlas.png`입니다. 빌드 시 무기의 기존 밝은 부분과 색상·발광 텍스처 마스크에 패턴을 적용합니다. 새 프레임이 실루엣 밖으로 번지거나 손잡이 전체가 점멸하지 않도록 제한하며, 보간하는 1.6~4초 루프입니다. 동적 광원이나 공격 순간에 발동하는 검기·잔상은 추가하지 않습니다. 기존 `_e` 파일에 새 클라이언트 모드 의존성을 추가하지 않습니다.

`python tools/verify_weapon_animations.py`로 원본 효과 보존·프레임 범위·알파·실제 모델 UV 위의 색상 변화를 검사합니다. `python tools/preview_weapon_animations.py`(NumPy·Pillow 필요)는 배포 ZIP의 모델·텍스처로 대표 9종의 PNG/GIF를 `tools/build`에 렌더링합니다. 비교를 위해 GIF의 테마별 루프 시간은 통일하며 실제 게임 캡처는 아닙니다.

리소스팩 수락/재다운로드가 필요하며, 운영 서버의 팩 SHA-1 변경과 실제 게임에서 1·3인칭·인벤토리 효과 확인은 별도입니다. 이 표면 효과는 아래 기본 공격 동작과 독립적으로 반복됩니다.

### 기본 공격 동작

단검은 기본 찌르기(`STAB`), 태도·대검은 기본 휘두르기(`WHACK`)를 사용합니다. Paper 26.3의 아이템 `attack_animation` 컴포넌트로 적용하며 별도 클라이언트 모드가 필요하지 않습니다.

모션 길이는 강화 단계별 공속에 맞춰 `20 ÷ 공속`을 가장 가까운 정수 틱으로 반올림합니다(20틱 = 1초). 단검은 0→25강에서 7→4틱(0.35→0.20초), 태도는 10→8틱(0.50→0.40초), 대검은 15→20틱(0.75→1.00초)입니다. 정수 틱 반올림으로 공격 게이지 충전 시간과 최대 0.025초 차이가 납니다. 새 지급·강화·기존 장비 갱신에 같은 규칙을 적용합니다.

이 설정은 공격 모션만 조절합니다. 공격 게이지와 피해 계산은 기존대로 유지하며 별도 강제 재공격 제한은 추가하지 않습니다. 실제 클라이언트에서 1·3인칭 모션과 연타 시 표시 확인이 필요합니다.

## 25강 고유 효과

| 무기 | 효과 | 발동·지속·대기 |
|---|---|---|
| 단검: 추격 | 이동 속도 +20% | 같은 대상에 유효 직접 공격 3회 명중 시 2초, 재발동 대기 5초 |
| 태도: 공방일체 | 받는 피해 10% 감소 | 유효 직접 명중 후 2초, 재명중 시 시간 갱신 |
| 대검: 압도 | 맞힌 대상 이동 속도 -30% | 같은 공격에 3마리 이상 실제 피해 시 1초, 재발동 대기 3초 |

단검/태도는 공격 게이지 85% 이상이고 취소되지 않은 실제 피해가 들어간 직접 타격만 발동에 집계합니다. 단검의 연속 명중 간격은 최대 2초입니다. 다른 대상/다른 무기 인스턴스/손 변경 시 연속 기록을 초기화하며 무기 교체로 5초 재사용 대기를 초기화하지 않습니다. 자신의 추격/공방일체 효과는 해당 25강 무기를 주 손에 들어야 유지합니다. 취소/피해 0 타격 및 같은 공격의 중복 대상은 압도 집계에서 제외합니다.

모두 자동 발동하며 실제 인챈트나 물약 효과를 붙이지 않습니다. 전용 임시 이동 속성만 추가/제거하여 기존 다른 버프·둔화는 보존합니다. 압도는 동시에 여러 번 걸려도 30%를 중첩하지 않고 종료 시각만 갱신합니다. 종료/언로드/로그아웃 시 전용 속성을 정리합니다. 공방일체는 기존 피해 구성 요소를 함께 90%로 줄여 방어력 재계산으로 감소율이 달라지는 것을 막습니다.

## 상인·강화·수리

- `/npc create armsmerchant` 또는 `/armsmerchantnpc create`: 전용 무기 상인 생성.
- `/armsmerchantnpc remove|face`: 상인 제거/방향 변경.
- `/armsshop [player]`: 관리자 구매 창. 집터 설치 후 종류별 0강을 각 1,000G에 구매합니다.
- 무기 상인은 대사 없이 바로 구매 창을 엽니다. 단검·태도·대검 이름은 각 슬롯 위에, 상품 툴팁은 가격만 표시합니다. 실제 장비에는 이름·강화 별·공격력 숫자 한 줄·25강 고유 추가 옵션을 표시합니다. 공격력은 해당 종류/강화 단계의 기본 공격력이며 개인 스킬·일시 버프는 포함하지 않습니다. 공속·사거리·드롭률·내구도와 사용 설명은 표시하지 않습니다. 외형은 남색 제복·모자·붉은 스카프·견갑·검집을 갖춘 전용 모델입니다.
- 기존 대장장이에서 확률·장기백·전용 결정·골드 비용을 공유합니다. 실패 단계 유지, 성공 시 내구도 완전 회복, 기존 수리 공방을 유지합니다.
- 전용 무기로 몹 처치 시 전투 스킬에 따른 확률로 결정을 얻습니다. `/enhance material dagger|tachi|greatsword <수량> [player]`도 지원합니다.
- `/villagetool give dagger|tachi|greatsword [level] [player]`: 관리자 지급.
- 내구도 소모 확률은 0~24강 100%, 25강 0%입니다. 25강 무한 내구도·드롭 아이템 화염 내성은 공통 보상입니다.
- 최대 내구도는 매 단계 증가하고 기존 장비 갱신 시 손상 비율을 보존합니다. 피격 무적 시간 전역 제거와 공격 게이지는 유지합니다.

## 바닐라 휩쓸기 제거 (4.12.0)

강화 무기는 검 태그에 속하지 않는 철/다이아 도끼 바탕으로 갱신해 바닐라 휩쓸기의 발생 조건을 제거합니다. 기존 무기는 손상 비율·강화·스킨·PDC를 보존해 전환됩니다. 리소스팩 모델과 단검 STAB/태도·대검 WHACK 공격 모션은 유지합니다. 도끼의 채굴 컴포넌트는 제거하고 방패 무력화 시간 0·공격당 내구도 소모 1로 지정합니다. 공격력·공속·사거리는 플러그인의 무기별 수치로 덮어씁니다. 리소스팩이 없으면 바탕 도끼가 보입니다.

기본 휩쓸기 피해 이벤트 취소와 휩쓸기 속성 0도 유지하여 플러그인 범위 공격만 적용합니다. 일반 바닐라 검은 변경하지 않습니다. 운영 서버에서 피해·효과음·입자와 실제 내구도/PvP 동작 검증은 별도입니다.
