# 기타 ServerCore 기능

이 문서는 NPC와 커스텀 도구·강화를 제외한 플레이 기능, 최초 설정, 저장 파일, 빌드·배포 정보를 모읍니다. 전체 명령은 [ServerCore 명령어](../플러그인/ServerCore.md)를 참고하세요.

## 플레이 기능

| 기능 | 사용법·요약 |
|---|---|
| 메뉴·이동 | 웅크리기+F 또는 `/menu`. 위치는 `/servercore setpoint <name>`으로 지정 |
| 도감 | `/dogam`, 발견 항목과 보상 기록 |
| 골드 | `/money`, 골드 주머니 입금·인출; 신규 계정 시작 금액 3,000G 고정 |
| 로비 시야 | `lobby`에서 야간투시 I 자동 유지. 입자·화면 아이콘 숨김; 인벤토리 효과 목록에는 표시 |
| 집터·부지 | 이장에게 집터를 받아 마을에 2×2 부지를 예약하고, 빚을 갚아 청크를 한 칸씩 해방 |
| 스킬·칭호 | 농사·채광·벌목·낚시·전투 성장, `/skill`, `/honor` |
| 히든 업적 | `/achievements`, 업적 칭호는 `/atitle`; 최초 달성 전에는 조건 숨김 |
| HUD·안내서 | `/hud`, `/guide` |
| 상점 | NPC를 클릭해 아이템 판매·구매; 상인(`farmplots`)이 비옥한 농지를 판매 |
| 농지 | 농지 상점에서 산 비옥한 농지를 해방된 내 집 부지에 설치. 물 공급을 유지하고 밟힘을 방지 |
| 순위 | 농사·채광·벌목·낚시 점수 누적, `/ranking`, 홀로그램 게시판 |
| 슬롯 머신 | 전용 블록 위의 대형 3릴 화면. 코인 한 개로 한 판, 2~5배 당첨금은 골드 잔액에 지급 |
| 이동 보조 | 관리자 `/jumppad`, 달리면서 점프하는 도약 |

## 코인 슬롯 머신

관리자 `/slotmachine [1~64] [player]`로 받은 전용 블록을 설치하면, 설치한 사람을 향하는 **가로 1칸·높이 2칸의 슬롯 머신 본체**와 그 위의 큰 슬롯 화면이 나타납니다. 본체는 적갈색 캐비닛·황동 테두리·777 간판·보석 슬롯 창·코인 투입구·배출구·빨간 레버를 갖춘 `servercore:slot_machine` 모델입니다. 회전 연출은 위의 공용 화면에서 진행하며 본체의 슬롯 그림은 장식입니다. 최신 JAR와 리소스팩을 함께 적용해야 전용 외형이 보이고, 이전에 설치한 기계도 재시작·청크 재로드 시 새 외형을 표시합니다.

큰 화면은 폭 약 4.8블록, 맨 위는 설치 위치보다 약 6.2블록 높으므로 주변 공간을 비워 주세요. 설치 시 바로 위 한 칸이 비어 있어야 하며, 설치 후 그 칸에 블록을 놓는 것도 막습니다. 본체 위쪽은 모형이고, 코인 투입·충돌·회수 기준은 아래쪽 실제 블록입니다. 리소스팩 기능을 끄면 자석석과 적갈색·금색 기본 블록으로 대체합니다. 다른 사람도 같은 회전을 봅니다.

`/money 100` 등으로 코인을 꺼낸 뒤 **주손에 들고 설치 블록을 우클릭**합니다. 한 판에 코인 한 개의 표시 금액만 사용합니다. 100G 코인 64개를 들어도 100G짜리 한 개만 쓰며, 웅크리거나 보조 손에 코인을 들어도 묶음 전체를 사용하지 않습니다. 코인을 그냥 공중이나 다른 블록에 우클릭하면 기존 잔액 입금 기능이 동작합니다. 서바이벌·모험 모드에서 이용할 수 있습니다.

| 같은 그림 3개 | 확률 | 100G 코인의 총 지급액 |
|---|---:|---:|
| 에메랄드 · 2배 | 25% | 200G |
| 금괴 · 3배 | 10% | 300G |
| 다이아몬드 · 4배 | 5% | 400G |
| 네더의 별 · 5배 | 1% | 500G |
| 서로 다른 그림 · 꽝 | 59% | 0G |

한 판당 독립 추첨으로 결과 하나를 선택하며, 배수는 **원금을 포함한 총 지급액**입니다. 전체 당첨 확률 41%, 이론 평균 환급률 105%이며 특정 판수에서의 결과를 보장하지 않습니다. 추첨·지급은 코인 투입 시 확정하고 골드 파일에 저장합니다. 이후 약 4.5초 동안 세 릴이 아래로 흐르며 왼쪽부터 감속·정지하고 결과를 3초 표시합니다. 회전이 끝나기 전 잔액에 보상이 보일 수 있습니다. 로그아웃·청크 언로드·플러그인 종료는 이미 확정한 보상을 취소하지 않습니다.

기계 한 대는 한 사람씩 사용하고, 한 사람도 동시에 여러 기계를 돌릴 수 없습니다. 회전·결과 표시 중 재클릭과 양손 중복 입력은 추가 코인을 소비하지 않습니다. 최대 5배 보상을 계산·입금할 수 없는 큰 금액은 추첨 전에 거절하며, 일반적인 저장 실패 시 코인과 잔액을 복원합니다. 코인 인벤토리와 골드는 별도 파일이므로, 두 저장 사이의 프로세스 강제 종료까지 하나의 원자적 거래로 보장하지는 않습니다.

기계 위치·방향은 월드 청크 데이터에 저장해 재시작·청크 재로드 후 화면을 복원합니다. 정상 파괴 시 전용 블록으로 회수하며 크리에이티브에서는 드롭하지 않습니다. 회전·결과 표시 중 회수와 폭발·피스톤 이동은 막습니다. ServerCore 집 땅 규칙에서는 설치·회수 권한을 지키면서 기계 이용은 공용으로 허용하고, 다른 보호 플러그인이 블록 사용을 차단하면 코인을 쓰지 않습니다. 엔티티 정리 플러그인은 `BlockDisplay`·`ItemDisplay`·`TextDisplay`를 제거하지 않도록 설정하세요.

`features.slots: true`가 기본이고 `features.economy`가 켜져 있어야 합니다. 기능 켜기·끄기는 서버 재시작 후 적용됩니다.

## 비옥한 농지

농작물 상인과 별도로 세운 ‘상인’ NPC의 `farmplots` 상점에서 한 개 **500G**에 삽니다. `/npc create farmplots`로 생성합니다. 비옥한 농지를 들고 본인이 사용할 수 있는 해방된 집 부지에 설치하면 일반 경작지와 같은 속도로 작물이 자라며, 엔티티가 밟아도 흙으로 변하지 않습니다. 물이 공급되어 수분이 오른 뒤 작물이 자라는 동안에는 수분을 유지합니다. 다 자란 작물을 캐면 수분이 0으로 초기화되어 다음 작물을 심기 전에 다시 물을 공급해야 합니다.

일반 괭이로 만든 밭은 기존보다 작물이 느리게 자랍니다. 비옥한 농지는 일반 밭의 기본 성장 속도를 유지하는 대신, 물 공급 유지와 밟힘 방지를 제공합니다. 기존 농사 경험치·순위 점수는 두 밭 모두 유지되며, 농지 블록을 캐면 아이템을 돌려받습니다. 가격은 `shops.yml`의 `shops.farmplots.items.farm_plot.buy`에서 바꾸고 `/servercore reload`로 적용합니다.

## 집터 사용

집터를 든 채 바닥을 가리키면 6블록 안에서 2×2 부지 미리보기를 볼 수 있습니다. 외곽은 높이 2블록의 반투명 유리벽으로 표시되고, 4블록 간격과 모서리에 빨간 세로 줄무늬가 보입니다. 웅크리고 우클릭해 북서→북동→남동→남서 모서리를 선택하고, 웅크리기를 풀어 우클릭하면 설치합니다. 선택은 재접속하면 북서로 초기화됩니다.

| 단계 | 기본 빚 |
|---|---:|
| 첫 집터 청크 설치 | 50,000G |
| 두 번째 청크 해방 | 150,000G |
| 세 번째 청크 해방 | 500,000G |
| 네 번째 청크 해방 | 1,000,000G |

이장에게 현재 빚 전액을 갚은 뒤 `/land` 집 지도에서 다음 청크를 해방합니다. 잠긴 칸은 집주인과 이웃도 사용할 수 없습니다. `/land trust <name>`·`/land untrust <name>`은 이웃 권한을 관리하며, `/land home`·`/land sethome`은 귀환 위치를 관리합니다. 집 포기·관리자 삭제는 건축물을 철거하거나 복원하지 않습니다.

집 설치 허용 구역은 village 월드에서 `/land zone pos1`, `/land zone pos2`, `/land zone add`로 정합니다. 선택은 청크 단위입니다. 범위를 비워 두면 마을 전체를 허용합니다.

`village`의 미소유 공용지에서는 일반 플레이어의 블록 설치·파괴·양동이·점화 등 변경을 막습니다. 집터 아이템으로 새 부지를 만드는 것만 예외이며 기존 부지 겹침·집 구역 검증을 거칩니다. 해방한 자기 부지와 명시적으로 허가받은 이웃 부지에서 건축할 수 있습니다. 공용 NPC와 문·버튼·상자·작업대 이용은 유지합니다. 다른 월드의 미소유 야생은 기존처럼 이용합니다.

**OP는 별도 명령 없이 공용지·다른 사람 집·잠긴 청크의 보호를 우회**합니다. 비OP 관리자의 `/land bypass`도 유지합니다. 집터 핵심 블록은 저장된 부지가 고아 상태가 되지 않도록 직접 파괴를 계속 막고 `/land delete`·`abandon`으로 처리합니다.

## 히든 업적과 칭호

생존·모험 모드에서 직접 점프 **10,000회**를 달성하면 ‘구름을 밟는 자’ 칭호를 받습니다. 신규 기능 적용 후부터 세며, 크리에이티브·관전·취소된 점프는 제외합니다. 점프 진행은 플레이어 PDC `servercore:hidden_jump_count`에 저장되어 접속 종료·재시작 후 이어집니다.

서버 최초 달성 전 `/achievements`에는 `???`만 표시합니다. 최초 달성 시 조건과 최초 달성자를 접속자에게 공개하고, 그 플레이어만 **30,000G + 전용 칭호 ‘하늘을 연 자’**를 추가로 받습니다. 이후 달성자는 일반 칭호만 받습니다. 일반 달성·칭호·보상 안내는 해당 플레이어와 로그에만 표시합니다. 최초 공개만 전체 공지입니다.

`/atitle`로 보유 업적 칭호를 확인하고 `/atitle equip cloud_walker`·`/atitle equip sky_opener`로 장착, `/atitle clear`로 해제합니다. 장착 칭호는 채팅·탭 이름 앞에 표시합니다. 기존 `/honor`에서도 업적 칭호 메뉴로 이동할 수 있고 스킬 칭호로 바꾸면 업적 칭호를 해제합니다. 자동 스킬 칭호 획득은 장착한 업적 칭호를 덮지 않습니다. 업적 칭호 해제 시 이전 스킬 칭호가 있으면 복원합니다. `/honor off`는 모두 해제합니다.

`achievements.yml`에 최초 달성자·각 달성자·선택 칭호를 함께 원자적으로 저장한 뒤 보상합니다. `money.yml`에는 잔액과 보상 지급 영수증을 같은 파일 교체로 저장해 재접속·재시작·재시도에 중복 지급하지 않습니다. 지급 저장 실패는 잔액·영수증을 되돌리고 최초 달성자의 다음 접속 때 재시도합니다. 기록 파일을 읽을 수 없으면 업적 기능을 중지해 최초 보상이 다시 열리지 않게 합니다. 두 파일을 함께 백업하세요.

## 순위 게시판

게시판을 둘 자리에 관리자 명령을 실행하면 글이 현재 위치보다 3블록 위에 표시됩니다.

```text
/rankboard create farm_top farming
/rankboard create mine_top mining
/rankboard create wood_top woodcutting
/rankboard create fish_top fishing
/rankboard list
/rankboard remove farm_top
```

기본 점수는 밀·당근·감자 1, 비트·호박 2, 네더 사마귀·코코아 3, 벌레잡이풀 8; 석탄·구리 2, 철 4, 금 6, 다이아몬드 20, 에메랄드 25, 심층암 에메랄드 40, 고대 잔해 50; 나무 1; 낚시는 대구 1·연어 2·복어 4·열대어 8·보물 20입니다. 게시판은 상위 10명을 5초마다 갱신하며 동점은 공동 순위입니다.

설치는 정상 채굴·수확·낚시만 집계합니다. 추가 드롭은 점수에 포함하지 않고, 설치 블록 재채굴·덜 자란 작물·취소된 작업·크리에이티브·관전은 제외합니다. `ranking.yml`에서 배점과 집계 월드를 설정하고 `/servercore reload`합니다. 점수·게시판 위치는 `ranking-data.yml`에 저장됩니다. 게시판을 지워도 점수는 유지됩니다.

## 최초 월드 설정

마을 메뉴의 기존 야생 버튼은 던전 버튼으로 표시하며, 이동 지점은 비워 둡니다. 워프 버튼은 메뉴와 같은 2×3 구성의 야생 이동 창을 엽니다. 왼쪽 위는 메뉴로 돌아가기, 오른쪽 위는 닫기입니다.

| 워프 창 위치 | 버튼 | 이동 지점 |
|---|---|---|
| 위 왼쪽 | 야생 중앙 | 기존 야생 저장 좌표 그대로 |
| 위 가운데 | 야생 북쪽 | 기준 Z −1000 |
| 위 오른쪽 | 야생 동쪽 | 기준 X +1000 |
| 아래 왼쪽 | 야생 서쪽 | 기준 X −1000 |
| 아래 가운데 | 야생 남쪽 | 기준 Z +1000 |
| 아래 오른쪽 | 준비 중 | 기능 없음 |

기준점은 `menu.yml`의 `warp-point`(기본 `wild`)이며 저장된 월드와 시선 방향을 사용합니다. 방향별 네 지점은 정확한 X/Z를 유지하고 비동기로 청크를 읽은 뒤 지표 높이에 맞춰 착지합니다. 물·용암 등 위험한 지표, 발/머리 공간 부족, 월드 경계 밖은 이동을 거절하며 다른 좌표로 옮기거나 지형을 바꾸지 않습니다. 중앙은 기존 야생 버튼처럼 저장된 Y까지 그대로 사용합니다. 이동 카운트다운은 기존 `config.yml` 설정을 공유합니다.

기존 기본 배치의 야생/준비 중 워프 버튼은 로드할 때 메모리에서 새 구성으로 전환합니다. 기존 야생 버튼에 별도 지점 이름이 있으면 새 워프 기준점으로 이어받습니다. 사용자 지정 명령·다른 슬롯 배치·명시적 `warp-point`는 유지하며 기존 설정 파일을 덮어쓰지 않습니다. 나중에 던전을 연결하려면 `buttons.dungeon.teleport`에 지점 이름을 넣고 `coming-soon: false`로 바꿉니다.

각 월드의 도착 지점에서 Multiverse 월드 스폰과 ServerCore 메뉴 지점을 각각 설정합니다.

```text
/mv setspawn
/servercore setpoint lobby
/servercore setpoint village
/servercore setpoint wild
```

이후 마을의 집 구역과 게시판 위치를 지정합니다. NPC를 세우고 일반 플레이어 권한으로 NPC 클릭·집터 설치·접근 권한·순위 표시를 점검합니다. Multiverse 월드 스폰과 ServerCore 메뉴 지점은 서로 다른 설정입니다.

## 설정 파일과 저장 데이터

서버의 `plugins/ServerCore/` 기준입니다. 기존 설정 파일을 새 JAR 파일로 통째로 덮어쓰지 마세요.

| 파일 | 역할 | 적용 |
|---|---|---|
| `config.yml` | 기능 켜기/끄기, 집터, 골드, HUD, 도약 | `/servercore reload`; 기능 활성화 변경은 재시작 |
| `menu.yml` | 메뉴 버튼·이동 지점 연결 | `/servercore reload` |
| `dogam.yml` | 도감 항목 | `/servercore reload`; 새 모델은 리소스팩 재빌드 |
| `shops.yml` | 상점 품목·가격·NPC ID (농지 기본 500G) | `/servercore reload` |
| `skills.yml` | 경험치·칭호·레벨 효과 | `/servercore reload` |
| `tools.yml` | 마을 도구·강화 확률·재료 드롭 | `/servercore reload` |
| `weapon-shop.yml` | 이전 가격 참고용; 괭이·물뿌리개 500G, 나머지 1,000G 고정 | 기존 `prices` 값 사용 안 함 |
| `ranking.yml` | 순위 배점·집계 월드 | `/servercore reload` |
| `guide.yml` | 서버 안내서 | `/servercore reload` |

`points.yml`은 메뉴 이동 지점, `lands.yml`은 집·예약 청크·빚·이웃, `land-zones.yml`은 집터 설치 구역, `ranking-data.yml`은 누적 점수·게시판 위치를 저장합니다. `money.yml`, `skill-data/`, `dogam-data/`에는 플레이어 데이터가 있습니다. 월드의 청크·엔티티 데이터에도 NPC와 설치 블록 기록이 있으므로 월드와 함께 백업합니다.

## 로비 야간투시

이름이 정확히 `lobby`인 월드에 접속·진입하거나 그곳에서 부활하면 야간투시 I을 자동으로 받습니다. 우유 등으로 해제해도 다음 틱에 재적용하며 2초마다 효과를 갱신합니다. 별도 권한·설정이나 리소스팩은 필요하지 않고 채팅 알림도 보내지 않습니다. 입자와 화면 오른쪽 효과 아이콘은 숨기지만, 바닐라 클라이언트의 인벤토리 효과 목록에는 야간투시가 표시됩니다.

로비를 나가거나 접속·플러그인을 종료하면 이 기능이 부여한 효과를 제거합니다. 기존 물약이나 로비에서 새로 마신 야간투시는 시간이 남아 있으면 원래 강도·표시 설정과 함께 복원하며, 우유·사망으로 제거된 효과는 복원하지 않습니다. 비정상 종료 시에도 무한히 남지 않도록 30초 효과를 갱신하는 방식이며, 재접속 시 저장된 로비 효과 표식을 정리합니다.

## 채팅 안내와 서버 로그

ServerCore의 NPC 대사·구매 결과·오류·명령 안내·칭호 획득 안내는 관련 플레이어나 명령 실행자에게만 전송됩니다. 다른 접속자에게 칭호 획득을 알리던 전체 알림은 제거했으며, 기존 `skills.yml`에 `title-broadcast`가 남아 있어도 사용하지 않습니다. 플레이어에게 보낸 채팅 안내는 `[ServerCore → 플레이어이름] 문구` 형식으로 서버 콘솔과 일반 서버 로그(`logs/latest.log`)에도 기록됩니다. 여러 줄은 줄마다 수신자를 표시하며 색상·클릭 서식은 제외합니다. 콘솔로 보낸 응답은 중복 기록하지 않습니다.

일반 플레이어 채팅의 공개 범위와 기존 채팅 로그는 그대로입니다. HUD·액션바·창 설명은 채팅 로그 대상이 아니며, 다른 플러그인이나 바닐라 서버의 전체 알림은 이 설정의 적용 대상이 아닙니다.

## 빌드와 배포

개발 환경은 Java 25입니다. `D:\Games\minecraft\Server\ServerCore_2`에서 다음 명령을 실행합니다.

```powershell
.\gradlew.bat clean build
python tools/build_pack.py --jar "$env:APPDATA\.minecraft\versions\26.3\26.3.jar" --dogam src/main/resources/dogam.yml
```

JAR는 `build/libs/ServerCore-<버전>.jar`, 전체 리소스팩은 `tools/build/servercore_pack.zip`에 생성됩니다. 플러그인과 팩은 별도로 배포합니다. JAR 교체 전 서버를 정상 종료하고 월드와 `plugins/ServerCore/`를 백업한 뒤, 기존 ServerCore JAR 하나를 새 파일로 바꾸고 재시작합니다. 적용 버전은 `/version ServerCore`로 확인합니다.

전체 서버용 팩은 GitHub의 [servercore 릴리스](https://github.com/deemo777/minecraft_server/releases/tag/servercore)에서 받습니다. 팩을 교체하면 다운로드된 ZIP의 SHA-1을 확인한 다음 서버 루트의 `server.properties`에 `resource-pack`과 `resource-pack-sha1`을 설정하고 서버를 재시작합니다. 현재 SHA-1은 [변경 기록](../../CHANGELOG.md)의 최신 리소스팩 갱신 항목을 참고하세요.

코드는 `src/main/java/com/htk/core/`, 리소스 생성기는 `tools/`에 있습니다. Git 원격은 `deemo777/minecraft_server`의 `plugins` 브랜치입니다. 월드, 저장 데이터, `.env`와 비밀 인증 정보는 소스 Git에 넣지 않습니다.

| 코드 경로 | 담당 |
|---|---|
| `ServerCore.java`, `common/` | 기능 초기화·공통 GUI·아이템·문자 |
| `land/` | 집터·부지·빚·보호·저장 |
| `tools/` | 도구·대장장이·강화·결정 |
| `npc/`, `mayor/`, `shop/`, `merchant/`, `cookie/` | 공통 NPC·이장·상점·잊혀진 명장·광쿠키 요리사 |
| `ranking/`, `skill/`, `hud/`, `dogam/`, `menu/`, `guide/` | 순위·스킬·칭호·HUD·도감·메뉴·안내서 |
| `slots/` | 코인 슬롯 확률·결제·설치 기록·공유 회전 화면 |

`gradlew.bat clean build`는 단위 테스트와 명령어·강화·집터·NPC 방향·구매·순위·슬롯 확률/정산 검증을 함께 실행합니다. 리소스팩 생성기와 모델·텍스처는 `tools/` 아래에 있습니다.

신규 골드 계정의 시작 금액은 3,000G 고정이며 기존 `config.yml`의 `economy.starting-balance` 값은 사용하지 않습니다. 기존 플레이어의 잔액은 유지합니다. 잊혀진 명장의 0강 도구는 괭이·물뿌리개 500G, 곡괭이·도끼·낚싯대 1,000G 고정으로 판매합니다.

## 광부 필요 경험치 (4.13.0)

광부는 1→10까지 기존 `50 + 40×레벨 + 3×레벨²` 필요 경험치를 유지합니다. 10→11부터 공통 기본값에 `1.5 + (현재 레벨-10)×0.05`를 곱하고 올림합니다. 농사·벌목·낚시·전투의 필요 경험치는 변경하지 않습니다. 기존 레벨과 현재 모은 경험치 값은 보존하며 새 요구량은 다음 경험치 획득부터 레벨업 판정에 적용합니다.

| 레벨업 | 기존 | 광부 변경 후 | 배율 |
| --- | --- | --- | --- |
| 9→10 | 653 | 653 | 1배 |
| 10→11 | 750 | 1125 | 1.5배 |
| 20→21 | 2050 | 4100 | 2배 |
| 30→31 | 3950 | 9875 | 2.5배 |
| 40→41 | 6450 | 19350 | 3배 |
| 49→50 | 9213 | 31785 | 3.45배 |

`skills.yml`의 공통 `curve.a/b/c`는 유지하고 `curve.mining.multiplier-at-10`(기본 1.5, 최소 1.5)과 `multiplier-per-level`(기본 0.05)로 광부 배율을 조절합니다. 기존 설정 파일에 새 키가 없어도 JAR 기본값을 적용합니다. HUD 경험치 숫자/막대·스킬 창·`/skill info`·실제 레벨업이 같은 직업별 계산을 사용합니다. Java 25 `gradlew.bat build`의 `verifySkillExperience`는 10레벨 경계·직업 분리·증가 배율·올림·여러 레벨을 한 번에 올리는 경우를 확인합니다.
